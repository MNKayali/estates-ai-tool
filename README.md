# Estates AI Tool

A gated web app that produces **UK RIBA Stage 0–1 feasibility reports** for construction and refurbishment projects. A user completes a structured questionnaire about their project; the app returns a fully costed, programmed feasibility report — viewable on screen and downloadable as a Word document.

Built with **Next.js 16** (App Router) and deployed on **Vercel**.

## How it works

The report is generated by a four-step pipeline (`app/api/generate-report/route.js`):

1. **Cost** — `lib/costCalculator.js` produces a deterministic NRM1 order-of-cost estimate.
2. **Programme** — `lib/programmeCalculator.js` produces a deterministic RIBA programme.
3. **Prose** — a single Claude API call writes the narrative sections (executive summary, key findings, risk register, constraints, procurement advice, next steps).
4. **Document** — `lib/reportBuilder.js` assembles a `.docx` from the numbers and the prose.

> **Core principle: the AI never calculates a number.** All costs, durations, and totals are computed deterministically from reference data. The AI is given those figures and writes prose around them — it is explicitly forbidden from recalculating or altering any value.

### Reference data

The cost and programme figures come from **Excel reference workbooks** fetched at runtime (rates, BCIS location factors, NRM1 scope mapping, percentage rules, and RIBA stage durations). Updating a rate or duration usually means editing the workbook rather than the code.

## Getting started

```bash
npm install
npm run dev      # http://localhost:3000
```

In local development with no `ACCESS_CODE` set, all routes are open and report persistence is disabled gracefully — you can run the full questionnaire-to-report flow without any external services configured beyond the API key and reference-workbook URLs.

### Other commands

```bash
npm run build    # production build (use this to validate before pushing)
npm run start    # serve the production build
npm run lint     # eslint
```

## Environment variables

| Variable | Purpose |
|---|---|
| `AI_API_KEY` | Anthropic API key for the prose-generation step |
| `RATES_FILE_URL` | URL of the NRM1 cost rates workbook |
| `PROGRAMME_FILE_URL` | URL of the RIBA programme durations workbook |
| `ACCESS_CODE` | Access code gating the app (if unset, all routes are open — dev only) |
| `KV_REST_API_URL` / `KV_REST_API_TOKEN` | Vercel KV for saving generated reports (optional; persistence is skipped if absent) |

Never commit `AI_API_KEY` or any secret. Store them in `.env.local` (local) or Vercel project settings (production).

## Access & persistence

- **Access control** — `proxy.ts` (Next.js 16's renamed middleware) requires a valid `estate_access` cookie for the questionnaire, report, and report APIs. The cookie is issued by `/api/check-access` when the correct `ACCESS_CODE` is entered at `/access`.
- **Saved reports** — generated reports are stored in Vercel KV for 90 days and retrievable at `/report/[id]`.

## Project layout

```
app/
  questionnaire/        Multi-step input form
  report/               On-screen report view (ReportRenderer.jsx) + /report/[id]
  access/               Access-code gate
  api/
    generate-report/    The 4-step pipeline
    reports/[id]/        Fetch a saved report
    check-access/        Issue the access cookie
lib/
  costCalculator.js     Deterministic NRM1 cost engine
  programmeCalculator.js Deterministic RIBA programme engine
  reportBuilder.js      Builds the .docx output
  kv.js                 Vercel KV wrapper (graceful no-op if unconfigured)
proxy.ts                Route access guard
```
